# Спецификация проекта «Финансовый планировщик» в формате User Stories

## Введение
Проект представляет собой веб-приложение для управления личными финансами, ориентированное на физических лиц. Основная цель — предоставить пользователю удобный инструмент для учёта доходов и расходов, формирования отчётов, а также получения персонализированных финансовых рекомендаций на основе искусственного интеллекта. Система строится на стеке FastAPI (backend) и React (frontend).

### Выделенные роли
- **Пользователь** — физическое лицо, использующее приложение для ведения личного бюджета, получения отчётов и советов.
- **Администратор** — сотрудник поддержки или разработчик, имеющий полный доступ к данным для решения инцидентов и модерации.

## User Stories

### Роль: Пользователь

#### 1. Учётная запись и аутентификация
| ID | User Story | Приоритет |
|----|------------|-----------|
| US‑01 | **Как пользователь, я хочу зарегистрироваться в системе, указав email и пароль, чтобы получить личный кабинет.** | Must have |
| US‑02 | **Как пользователь, я хочу входить в систему с помощью email и пароля, чтобы иметь доступ к своим данным.** | Must have |
| US‑03 | **Как пользователь, я хочу иметь возможность восстановить пароль через email, чтобы не потерять доступ к аккаунту.** | Should have |

**Критерии приемки для US‑01, US‑02:**
- Поля email и пароль валидируются (email уникален, пароль не менее 8 символов).
- После регистрации пользователь автоматически входит в систему или перенаправляется на страницу входа.
- Сессия сохраняется (JWT или cookie) при перезагрузке страницы.

#### 2. Управление категориями
| ID | User Story | Приоритет |
|----|------------|-----------|
| US‑04 | **Как пользователь, я хочу создавать, редактировать и удалять собственные категории доходов и расходов, чтобы классифицировать транзакции под свои нужды.** | Must have |
| US‑05 | **Как пользователь, я хочу видеть список всех моих категорий с возможностью быстрого выбора при добавлении транзакции.** | Must have |

#### 3. Добавление транзакций (доходы/расходы)
| ID | User Story | Приоритет |
|----|------------|-----------|
| US‑06 | **Как пользователь, я хочу вручную добавлять доходы и расходы с указанием суммы, даты, категории и комментария, чтобы вести точный учёт.** | Must have |
| US‑07 | **Как пользователь, я хочу редактировать и удалять ранее добавленные транзакции, чтобы исправлять ошибки.** | Must have |

**Критерии приемки для US‑06:**
- Форма содержит поля: сумма (число), дата (календарь), категория (выпадающий список), тип (доход/расход), комментарий (опционально).
- После сохранения транзакция сразу отображается в ленте или в соответствующем отчёте.
- Валютой по умолчанию является рубль (возможность выбора валюты — в будущих версиях).

#### 4. Голосовой ввод транзакций с помощью AI‑ассистента
| ID | User Story | Приоритет |
|----|------------|-----------|
| US‑08 | **Как пользователь, я хочу надиктовывать голосом информацию о трате или доходе (например, «потратил 500 рублей на обед»), чтобы ассистент автоматически создавал транзакцию без ручного ввода.** | Must have |

**Критерии приемки:**
- На странице добавления транзакции есть кнопка «Голосовой ввод».
- При нажатии начинается запись с микрофона (с запросом разрешения).
- Распознанный текст анализируется AI: извлекается сумма, категория (если возможно), тип (доход/расход), дата (по умолчанию текущая).
- Если AI не может определить категорию, пользователю предлагается выбрать из списка или создать новую.
- Транзакция создаётся после подтверждения пользователем или настраиваемого правила автосохранения.
- Обработка ошибок: если голос не распознан, выводится сообщение с предложением повторить или ввести вручную.

#### 5. Отчёты и аналитика
| ID | User Story | Приоритет |
|----|------------|-----------|
| US‑09 | **Как пользователь, я хочу видеть Balance Sheet (обзор текущих остатков, активов, агрегированных трат за предыдущие периоды) в виде дашборда, чтобы быстро оценить финансовое состояние.** | Must have |
| US‑10 | **Как пользователь, я хочу получать отчёт о движении денежных средств (ДДС) с группировкой по категориям за выбранный период, чтобы анализировать структуру доходов и расходов.** | Must have |
| US‑11 | **Как пользователь, я хочу просматривать простые графики (круговые диаграммы, столбчатые) по категориям расходов и доходов, чтобы наглядно видеть распределение.** | Must have |

**Критерии приемки для US‑09:**
- Дашборд содержит: текущий баланс (сумма всех доходов минус расходы), активы (если есть инвестиционный учёт), график трат по дням/неделям, сравнение с прошлым периодом.
- Данные обновляются в реальном времени при добавлении/изменении транзакций.

#### 8. Анализ данных с помощью LLM (рекомендации)
| ID | User Story | Приоритет |
|----|------------|-----------|
| US‑15 | **Как пользователь, я хочу отправить свои финансовые данные в специальную обученную нейросеть, чтобы получить персонализированные рекомендации по бюджету, накоплениям и оптимизации расходов.** | Must have |

**Критерии приемки:**
- На странице аналитики есть кнопка «Получить AI‑рекомендации».
- При нажатии данные пользователя (анонимизированные или с его согласия) отправляются на сервер, где обрабатываются LLM.
- Рекомендации возвращаются в удобочитаемом виде (список советов, выделение проблемных категорий, предложения по норме сбережений).
- Пользователь может сохранить или поделиться рекомендацией.
- Предусмотрено информирование пользователя о том, что данные обрабатываются нейросетью и не передаются третьим лицам.

| ID | User Story | Приоритет |
|----|------------|-----------|

| US‑A02 | **Как администратор, я хочу иметь доступ к любой транзакции любого пользователя (просмотр, редактирование, удаление) для исправления ошибок или обработки жалоб.** | Must have |

## Примечания и дополнительные требования

1. **Архитектура и безопасность:**
   - Весь обмен данными должен производиться по HTTPS.
   - Пароли хранятся в БД в захэшированном виде (bcrypt).
   - Доступ к AI‑функциям (голосовой ввод, рекомендации) должен быть явно разрешён пользователем (согласие на обработку голоса и данных).
   - Реализовать защиту от CSRF и XSS.

2. **AI‑компоненты:**
   - Для голосового ввода используется Speech-to-Text API (например, Яндекс SpeechKit или OpenAI Whisper) с последующим NLP для извлечения сущностей.
   - Для рекомендаций планируется fine-tuned LLM (например, на базе GPT или отечественных моделей). Необходимо предусмотреть механизм анонимизации данных перед отправкой в модель.

3. **Интеграции:**
   - Интеграция с банками (US‑18) потребует подключения к API банков через OpenAPI или использования агрегаторов (например, Yodlee, Plaid для РФ — аналоги). В MVP этот функционал может быть заменён импортом выписок.

4. **Масштабирование:**
   - Учитывая возможность роста числа пользователей, backend должен быть построен с учётом горизонтального масштабирования (использование очередей для AI‑задач, кэширование отчётов).

5. **UX/UI:**
   - Интерфейс должен быть адаптивным (desktop-first, но с возможностью использования на планшетах).
   - Для голосового ввода необходим понятный индикатор записи и обратная связь.
